# Gemini 模型交付协议 v1.1

更新：2026-11-28（v1.1：商品热点按部件清单、无统一上限；光外溢已确认）· 类型：**增量补录协议**，补充《Gemini 设计协议 v2.1》，不替代它。
适用对象：Gemini 对 **商品模型、全生态模型、智能体** 的设计交付。

## 1. 定位与边界

- Gemini 仍然只做设计，**不建造模型**。本协议里的 L3 "模型预演"用的是**预演代理体**（灰模/占位模型 + html/glb 预演），用来演示"这个模型该怎么被看、被点、被动、被照亮"，**不是生产资产**。
- 代理体必须命名 `PROXY_*`，文件元信息写 `PROXY-NOT-FOR-PRODUCTION`；施工方不得把代理体直接上线或当作成品。
- 谁来建：商品模型→Antigravity；生态模型→按 L5 ASSET_MAP 的 owner（ag 或 cu）；智能体→Cursor。建造标准：Cursor 的生态模型按**精细度**，Antigravity 的按**维度**。

## 2. 与主协议的关系

L1–L5 的级别、文件处理、PRESENT_LOG、变更等级、用户指令**全部沿用主协议**。本协议只规定模型/智能体特有的内容：**L3 的 r 档**、模型专项质检、L5 的模型字段。工具使用与质量门沿用主协议 §3A（多工具可用，不得浪费）。

## 3. L3 默认三档：r1 / r2 / r3

每个模型（或智能体）在 L3 **默认交付 r1、r2、r3 三份预演**。三档**累进**：r2 包含 r1 的全部，r3 包含 r2 的全部。用户可在立项时删减某档，须写明理由。

| 档 | 一句话 | 要点 | 不包含 |
|---|---|---|---|
| **r1** | **模型使用**：看着、细节都够 | 模型作为被观看/使用的对象；在**目标视距与目标屏宽**下，关键细节全部可辨；允许用户自己旋转/缩放 | 热点；自带 3D 动效；超出光晕规则的发光 |
| **r2** | **扣热点 + 逐步开放自带 3D 动效** | 把模型上值得交互的位置"扣"成热点（可点/可悬停/可聚焦）；模型自带的 3D 动效**按梯度逐步开放** | 中心主角化；光污染 |
| **r3** | **中心大模型化**，允许**光污染** | 模型成为页面/场景的中心主角（尺度占主视觉）；允许发光外溢 | — |

### 3.1 r1 判据（可测）
- 交付一份 **细节清单**：逐项命名（如"接缝光线""倒角""铭牌刻字"），每项在目标视距下给出 100% 与 200% 两张证据图，"看得清/看不清"二值判定；全部"看得清"才算 r1 完成。
- 无热点、无自带动效；动作只有用户手动旋转/缩放。
- 光：仅按 PALETTE 的 seam-aura 规则（≤3% 面积、不承载文字）。

### 3.2 r2 判据（可测）
- **热点表**：每个热点有 id、分组、命名位置（模型骨架点/部件名）、触发（点/悬停/聚焦）、反馈、回落、键盘可达方式。
- **热点数量规则（按对象）**：
  - **商品模型：不设统一上限，数量由商品的"可交互部件清单"决定**——每个可被单独辨识、消费者会单独关心的部件，至少 1 个热点。例：**巧克力礼盒热点至少 16 个**（实际颗数/部件多于 16 则按实际，不得少于 16）。L5 为每个商品写明 `hotspot_min`，Gemini 的热点表条数不得低于它。
  - 全生态模型、智能体：沿用建议值——每模型 ≤5 个，移动端 ≤3 个（待确认；你只对商品调整了数量）。
- **热点多时的配套要求（商品）**：
  1. **可达性**：全部热点有唯一命名与键盘顺序，并提供"热点列表"作为不依赖 3D 点选的替代入口。
  2. **同屏可见数**：同一视角下同时显示的热点数由 L5 规定；移动端允许**聚簇/分页/按分组展开**，但**总数不减，每个热点仍可到达**。
  3. **触控**：热点点击区与间距须达标（建议 ≥44px，WCAG 最低 24px）；密集处用聚簇或放大后再展开。
  4. **轻量**：热点是标注层，不得为每个热点另起一个 Hot 3D；不得因热点多而突破 Hot 预算。
  5. **SEO**：部件名与简短说明作为页面可抓取文本输出（D-08a），不只存在于 3D 里。
  6. **顺序**：热点区不得把 Trust 信息挤出移动端首屏（D-09）。
- **动效开放表**：把模型自带的 3D 动效逐条列出（clip 名、时长、触发、是否循环、`prefers-reduced-motion` 下的行为），并按梯度开放：
  - C1 触发型（点/悬停才动）→ C2 环境型（轻微待机循环）。
  - r2 最多开放到 C2；每开一条要写**为什么开**。C3（多段编排/大幅运动）留给 r3。
- 热点必须有无动效的替代（减少动效模式下仍可操作）。

### 3.3 r3 判据（可测）与"光污染"的边界
r3 允许模型发光/接缝光**外溢**，这与 PALETTE 的 seam-aura（≤3% 面积）冲突，因此 **r3 的光污染是"预授权琥珀"**：需你在立项时一次性确认；L4 写出具体数值。边界：
1. 光只能外溢在**模型自己的舞台容器内**；**不得覆盖任何文字、CTA、Trust 信息**；文字区对比度仍须达标。
2. **不得借光污染改动 paper / paper-subtle / seam-aura 的取值**，也不得改变页面底色。
3. 色相只能用 seam 色带（216–221°）与光晕 `#E5FFFF`；不引入新的发光色。
4. 外溢面积、亮度上限写进"光效预算"。**已确认上限：外溢不超过舞台容器的 40%、不超过视口的 20%**（2026-11-28 确认）；预算内可以更小，不可更大，更大需 T3。
5. 同屏 Hot 仍 ≤3；r3 的中心大模型计 1 个 Hot。
6. `prefers-reduced-motion`/低性能/弱网下，光污染静态化或关闭，降级到 r2。
7. 允许 C3 动效，但首屏 Trust → Motivate → Remember 的顺序不得被模型挤掉（D-09）；移动端首屏默认不得因 r3 而看不到 Trust 信息。

### 3.4 降级链（每个模型必须有）
`r3 → r2 → r1 → 海报（Cold 静图）`。触发条件：减少动效、弱网、低性能、WebGL 不可用、关闭季节/关闭模型。每一步在预演里都能一键触发。

### 3.5 建议的默认档位（与 DNA 强度档挂钩，**待确认**）
| 页面强度档 | 模型默认目标档 |
|---|---|
| 高（Home/Scene/Season） | 可到 r3 |
| 中（Bundle/MTO） | 到 r2 |
| 低（PDP/Collection） | 到 r1（商品页个别主推可 r2） |
| 最低（Cart/Checkout） | 无 3D |
这只是建议默认值；每个放置点的**目标档**最终写进 L5（`r_target`）。

### 3.6 三类对象的 r 档含义
| 对象 | r1 | r2 | r3 |
|---|---|---|---|
| 商品模型 | 能看清商品细节（材质/接缝/做工） | 商品关键部位热点（如结构、材质、尺寸点）+ 自带开合/展开等动效 | 商品成为页面主角，允许受控发光 |
| 全生态模型 | 作为场景元素被看清 | 场景内热点（可跳转/可聚焦）+ 生态联动动效 | 生态模型作为场景中心，允许受控光效 |
| 智能体 | G-0 槽位（⌀24mm 虚线圈）静态在场 + 状态指示 | 智能体可指向/高亮模型热点、触发生态模型自带动效 | 智能体成为中心主角（大尺度），允许受控光效 |
智能体档位的含义是我按"可调用全部生态资产"的约定推出的，**请你确认**。

## 4. L3 交付物与目录

```
model-product/<sku>/Gemini/L3/
model-ecosystem/<id>/Gemini/L3/
agent/<事项>/Gemini/L3/
   README.md            总说明 + r1/r2/r3 对照表 + 如何打开 + 降级链演示
   r1/  README.md + PROXY_* + 预演（html/glb）+ 细节清单与证据
   r2/  README.md + 热点表 + 动效开放表（含 r1 全部）
   r3/  README.md + 光效预算 + 舞台容器说明（含 r2 全部）
   L3D/ 七张灰度示意图
```
每个 r 档的 README 固定包含：目的 · 如何打开 · 与上一档的差异 · 细节清单/热点表/动效表/光效预算（按档） · 降级触发与表现 · 与 L5 字段的对应 · 已知不做。
L3 的文件处理沿用主协议：退回更新删旧留新，PRESENT_LOG 留痕（含工具用量与 r 档状态）。

## 5. 质检门（DQ-M，交付 L3 前自检，数值写进 README）

- 细节可辨性：每个命名细节有 100%/200% 证据与二值判定。
- 商品热点表条数 ≥ L5 的 `hotspot_min`，且每条有唯一命名；热点表/动效表**可测**：每行有触发、反馈、回落、reduced-motion 行为。
- 光效预算有数值（面积占比、亮度、色相），并核对文字对比度未被破坏。
- 降级链每一步都能演示。
- 代理体命名 `PROXY_*`、含 `PROXY-NOT-FOR-PRODUCTION`，且体积/面数在代理预算内（不追求成品精度，避免资源浪费）。

## 6. L4 对模型的专项检查（落在 D-01…D-09 内，不新增维度）

- **色相合规**：材质按令牌映射，色相落在 PALETTE 带宽（metal 216–225°，seam 216–221°）。
- **预算**：Hot 每屏 ≤3/全站 ≤4；r3 计入。
- **光污染（仅 r3）**：写出外溢面积、亮度、文字对比度；列为 AMBER-R3 并附你的批准。
- **D-08 渠道**：Cold 海报是可抓取的图片 + 替代文本（桌面 SEO）；移动端首屏体积与首屏可见 Trust 信息（快承接/转化）；r2/r3 在移动端是否降档。
- **D-09 顺序**：模型不得把 Trust 信息挤出首屏；Motivate 与 Remember 的落点不被模型动效抢夺。

## 7. L5 的模型字段（写入 ASSET_MAP / AGENT_ASSET_REGISTRY）

每个模型/智能体放置点必须有：
`id` · `类别` · `owner(ag|cu)` · `衡量标准(精细度|维度)` · **`r_target`（每个放置点：页面/屏/档位）** · 细节清单（引用 L3） · 热点表（含 `hotspot_min`、分组） · 动效开放表 · 光效预算（r3） · 相机与视距 · 面数/体积/LOD 预算 · 材质→令牌映射 · 海报与替代文本 · 降级链 · Promote 状态 · 智能体调用事件名。
施工规则：**建到 `r_target` 为止**；超出 `r_target` 不做；低于视为未完成；降级链必须实现。

## 8. 与施工方的接口

- 施工方在 `VERIFY` 里逐档给证据（r1 细节证据、r2 **逐个热点**的证据、动效证据、r3 光效数值）。
- 施工方想把某处升到更高的档或更大的光效 → 变更单（T2；涉及光污染边界变动为 T3）。
- Antigravity 的模型变体（1–2 个）若探索更高一档，须在 `MODEL_VARIANT_RATIONALE` 里说明，且不得越过本协议 §3.3 的边界。

## 9. 确认状态
**已确认**：光外溢上限（舞台容器 ≤40%、视口 ≤20%）；商品热点按部件清单、巧克力礼盒 ≥16。
**仍待确认（建议值）**：1) 生态模型/智能体的热点上限 5/3；2) §3.5 默认档位映射；3) 智能体 r 档含义；4) r3 光污染作为"预授权琥珀"，由你在立项时一次性确认（我对你"光外溢确认"的理解是确认了上限数值，预授权方式仍沿用）。
