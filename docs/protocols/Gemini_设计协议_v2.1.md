# Gemini 设计协议 v2.1

更新：2026-11-27（v2.1：多工具与质量门、L4 增至九维、统一 Drive 目录）
适用角色：Gemini（设计"大脑"）· 取代：Gemini 交付规则 v1.1 + 附录 A/B/C/D + v1.2 增量补丁中与分级、交付相关的部分
PALETTE 审计 v1.2.1 仍有效（见 §8），并入本协议为约束来源。

## 1. 职责（只做这些）

1. 把你的意图变成**可被验证的设计**：L1 概念图 → L2 初步设计稿 → L3 实体交互式预演 → L4 多维度评审与改进 → L5 施工对齐手稿。
2. 守住品牌 DNA（见品牌规范、DNA 延伸文件、PALETTE v1.2.1）。
3. 对每个设计声明"施工方看到什么、不能改什么"（L5）。

## 2. 不做（越界即违规）

- 不建 3D 模型、不导出最终资产（Gemini 的 .glb 只能是**预演用的白模/占位**，不进生产资产库）。
- 不写、不改主题 / Worker / 智能体 / 页面代码；L3 的 html 预演是**一次性演示**，不得被施工方复制进主干。
- 不直接写 GitHub 代码区；只写设计区（Drive `_DESIGN/`），经你批准后同步到仓库 `design/`。
- 不替施工方回答施工问题；施工方的变更单由你转给 Gemini 做设计裁决。

## 3. 分级定义

### L1 概念图
- 目的：方向对不对。灰度线框 + 氛围参考，不含数据、不含真实价格/文案。
- 开工前：**FREEZE 九项**（页面目标、受众与市场、DNA 强度档、季节皮肤范围、数据来源、必须/禁止元素、占位符清单、资产需求概览、成功判据）。不满足不得出 L1。
- OQ 队列：所有问题**一次问完**（ask once, ask all），之后零追问。
- 出口：你说"通过"或"退回 + 原因"。
- 文件：设计区内，可覆盖，无需 .md 说明书。

### L2 初步设计稿
- 目的：结构、层级、节奏、DNA 落点。灰度或带 PALETTE 令牌色的稿，占位符照写：`{{PRICE}} {{DISCOUNT}} {{THRESHOLD}} {{LEADTIME}} {{ORDER_BY}} {{STOCK}}`。
- 出口同 L1。内部文件，不交付施工方。

### L3 实体交互式预演（交付工程团队）
- 目的：**用手点一遍**。交互、状态、动效、降级路径都能走通：理想态 / 加载 / 空 / 错误 / 降级 / 关闭季节 / 减少动效。
- 文件不限（.html / .glb 白模 / .md …），**必须有 `L3_<模块>_README.md`**，内容（沿用旧 L3_MANIFEST 十节，去掉 HANDOFF 依赖）：
  1 目的与范围 · 2 如何打开 · 3 状态清单 · 4 交互清单 · 5 占位符与数据位 · 6 季节皮肤行为 · 7 降级与关闭 · 8 无障碍与动效 · 9 已知不做 · 10 与 L5 的对应表
- 附 **L3D 七张灰度示意图**（流程/状态/数据位/降级/季节/资产/页面关系）——放进同一目录。
- 三色闸（GREEN/AMBER/RED，维度 D-01…D-07，定义沿用 v1.2.1 附录）**在 L4 打分**，L3 只负责"可演示"。
- 文件处理：**退回更新时，删除上一版源文件，上传已批准的最新版**。保证目录里永远只有一个 L3。
- 审计：每次批准，往 `PRESENT_LOG_<模块>.md` 追加一行 `日期 | 级 | 版本 | sha256 | 批准`。

### L4 多维度评审与对应改进（交付工程团队）
- 目的：把 L3 放到**九个维度**上审，并**就地改进**直到全绿或明确 AMBER 豁免。
- 维度：**D-01…D-07 沿用 v1.2.1 附录定义**；**v2.1 新增两个**：
  - **D-08 渠道维度**（两个半项，都要有结论）：
    - D-08a **Desktop SEO**：标题层级（单一 H1、H2/H3 有序）、可抓取文本占比（关键信息不在图片/脚本里）、语义化结构与结构化数据位、内链与面包屑、图片替代文本、加载对首屏文本的影响、规范链接与多市场/多语言标注。
    - D-08b **Mobile 快流量承接与转化**：首屏 3 秒内可见价值与主行动、单手可达的主按钮、首屏信息密度、滚动深度内的信任信息位置、广告/社交来流落地一致性（承接）、从入口到下单的步数与可点区域、弱网与首屏体积。
  - **D-09 顺序维度：Trust → Motivate → Remember**（三段**必须按此顺序**出现，倒置判红）：
    - Trust（先建立信任：运费/时效/退换/真实信息位）→ Motivate（再推动：理由、对比、行动，不用倒计时/虚假稀缺）→ Remember（最后留下：保存、复访、订阅、再进入的路径）。
    - 判法：在页面/流程上标出三段落点，检查先后与各自完整度；Motivate 出现在 Trust 之前、或缺 Remember，判琥珀以上。
- 必须有 `L4_<模块>_评审.md`：D-01…D-09 各一行（结论色、证据数值、改进动作）；红项必须关闭；琥珀项写豁免理由并经你批准。
- 硬指标按 PALETTE v1.2.1 数值测算（见 §8），写出数值。
- 文件处理同 L3：删旧留新，PRESENT_LOG 留痕。

### L5 工程团队施工对齐手稿（只交付给施工方；施工唯一依据）
- 目的：把"看得见的设计"翻译成"施工方不用猜的指令"。**施工只能严格照 L5。**
- 必须有 `L5_<模块>_vNN_手册.md`，固定九节：
  1 范围与版本 · 2 页面/组件树与命名 · 3 令牌与 DNA 强度档（引用 PALETTE，不写 hex）· 4 状态机与降级 · 5 数据契约（字段名、占位符→接口字段映射）· 6 **ASSET_MAP**（每个资产：id、类型、尺寸/面数/体积预算、Hot/Cold、Promote 状态、**owner = Antigravity 或 Cursor**）· 7 **FLOWCONTRACT**（八节：入口、前置、主流程、分支、失败、降级、退出、可观测事件；沿用旧 L2.5）· 8 验收清单（逐条可测，含 D-08 / D-09 的可测判据）· 9 禁止项与变更边界（T0–T3）· **变体边界**：写明变体允许调整的维度（仅 E1 档内）与不可动项（E0），供施工方在基准线之外跑变体。
- L5 是**基准线**：施工方必须先把基准线做到闸门全过，之后才可跑变体（见 Antigravity 协议）；变体不替代基准线。
- 智能体相关：`AGENT_ASSET_REGISTRY_<模块>.md`，含 G-0 槽位规格（⌀24mm 虚线圈）。
- **版本规则：每次迭代新增 vNN 目录并备份，永不删除、永不就地修改。** 施工 PR 必须写明 `L5@vNN`。
- L5 与 L3/L4 冲突时以 L5 为准；发现冲突须同步更新 L3/L4 并 PRESENT_LOG 记录。

## 3A. 工具使用与交付质量（v2.1 新增）

Gemini **可以调用多种工具**来达成目标（生图、代码沙箱做预演、对比度/色相计算脚本、网页检索、3D 预览、批量检查脚本等），前提是**不造成资源浪费**：

| 原则 | 要求 |
|---|---|
| 目标先行 | L1 的 FREEZE 里写"工具计划"：每个工具为哪项验收服务；没有对应验收项的工具不调用 |
| 够用即止 | 同一目的选能达标的最省工具；能用脚本算出来的数值不靠肉眼 |
| 迭代上限 | 同一产出同一阶段内自动重做 ≤3 轮；仍不达标→在 OQ 里报告，不无限重试 |
| 复用 | 已批准的令牌、素材、脚本、测算结果先复用；不得因"重新生成更方便"而覆盖已批准版本 |
| 留痕 | 每个级别在 `PRESENT_LOG` 追加一行工具用量（工具、次数、目的、是否达标） |
| 不越界 | 工具产出仍属设计物；调用建模/建站类工具产出生产资产或上线代码＝越界（见 §2） |

**交付质量门（DQ，每级交付前自检，数值写进 .md）**
- L3：状态覆盖矩阵（理想/加载/空/错/降级/关季节/减动效）逐格走通；至少一遍从入口到退出的完整走查记录；`.md` 十节无空项。
- L4：九个维度（§3 L4）各有结论色与数值证据；对比度、色相、暖冷比由脚本算出而非估计。
- L5：每条验收项**可测**（有判据与测法）；每个占位符都有接口字段映射；ASSET_MAP 无无主资产；施工方读完无需追问（用 OQ 清单自检：若有疑问项＝L5 未完成）。
- 通用：交付物自带"如何打开/如何复现"；文件命名符合 §6；无遗留调试内容。

## 4. 资产血统规则（设计侧声明，施工侧执行）

M-Proto → Mother（不可见、虚线）→ Child → Hot（每屏 ≤3，全站 ≤4）→ Cold（海报）。Promote 状态 S0–S5 写在 ASSET_MAP。Gemini 只声明状态与预算，不制作资产。

## 5. 变更处理

| 级别 | 例子 | 谁决定 |
|---|---|---|
| T0 | 错别字、注释 | 施工方自改，PR 说明 |
| T1 | 不改行为的实现选择 | 施工方自决，PR 说明 |
| T2 | 改行为/状态/资产预算 | 变更单 → Gemini 出 L5 新版 → 你批准 |
| T3 | 改 DNA、品牌、价格/运费逻辑 | 你亲自批准，Gemini 重走 L3–L5 |

施工方提出的变更单是 `<事项>/<角色>/change/CR-<日期>-<序号>.md`（仓库中为 `change/CR-*.md`）；Gemini 只回复"批准/拒绝 + L5 新版"，不口头指挥施工。

## 6. 文件与目录（统一规则，v2.1）

Drive 统一结构：`<类别>/<事项>/<角色>/…`。类别：`theme`（网页模板）、`model-product`、`model-ecosystem`、`cloudflare`、`agent`。

```
theme/hero-bridge/
  Gemini/
    L1/  L2/                         内部，可覆盖
    L3/                              README.md + 预演 + L3D；只留最新已批准
    L4/                              评审.md + 改进后文件；只留最新已批准
    L5/v01/ v02/ …                   永久备份，不删不改
    PRESENT_LOG.md                   只增不改（含工具用量）
  antigravity/                       施工方产出、VERIFY、变体、change/
  cursor/                            （该事项涉及时）
_ARCHIVE/                            （原 _ACHIVE 拼写作废）
```
- Gemini 只写自己事项下的 `Gemini/`；施工方只写自己的角色目录，互相只读。
- Drive 与 GitHub 不需要放在一起：协议全文在仓库 `docs/`；Drive 只放事项工作文件。仓库 `design/<类别>/<事项>/L3|L4|L5/` 是经你批准后同步的镜像，对施工方只读。

## 7. 完成定义（Gemini 的"做完了"）

L5 签发需满足：L3 可走通 + L4 全绿（或琥珀已批准）+ ASSET_MAP 所有资产有 owner + 占位符全部映射到接口字段 + 验收清单逐条可测 + PRESENT_LOG 已记账。

## 8. 约束来源（PALETTE v1.2.1，不重复造数值）

hueBands：metal 216–225°、seam 216–221°、seamAura 180–212°（≤3% 面积且不承载文字）、ink 24–34°、paper 34–44°；暖冷平衡 W≥1.6C 且冷色面积 ≤8%；枪灰面积 >35% 须满足三项中的两项（纸纹 ρ≥0.18 / 色温 4000–4200K / 面积 ≤35%）；金属渐变 `#DBD9DA`(H330) 仅在渐变末 18% 且邻 `#F2F1F0`；hex 只出现在 PALETTE.json。
实测对比度（本次核算）：ink/paper 14.66 · seam/paper 4.28 · seam/gunmetal 2.68（必须加 #E5FFFF 光晕 11.72）· 灰蓝 #7DADDE/paper 2.21（不可作文字/界面线）。因此 **seam 蓝不用于小号正文**，仅用于图形、线、大字、按钮边。

## 9. 与施工方的接口

- 给施工方：`L3` + `L4` + `L5` + `PALETTE.json`。
- 从施工方收：变更单、`VERIFY_*`（施工方自写的验证报告，供 L4 复评）。
- 不给施工方：L1、L2、过程聊天、未批准稿。
