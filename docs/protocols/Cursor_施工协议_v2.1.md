# Cursor 施工协议 v2.1

更新：2026-11-27（v2.1：精细度标准、TRACK 续作机制、智能体与资产关系、统一 Drive 目录）

适用角色：Cursor（施工方 B）· 取代：Cursor 生产协议（含 v1.2 增量补丁）中的职责与分工条款

## 1. 职责

1. **Cloudflare**：Workers + D1（market-festival、shipping-intelligence、bundle、MTO 等）、路由、绑定、环境、部署、观测；**接口契约 `contracts/`** 的唯一维护者。
2. **智能体开发**：智能体逻辑、对话/工具调用、G-0 槽位的运行时对接（`AGENT_ASSET_REGISTRY` 所定义）。
3. **3D 模型资产（以精细度为衡量标准）**：L5 ASSET_MAP 中 `owner = Cursor` 的**生态模型**（默认：随智能体/Worker 数据驱动的形体与可视化，如智能体 G-0 形体）。商品模型**不是**它的范围。
4. 交付 `VERIFY_*`。

## 2. 不做

- 不改主题与前台页面（`web/**` 归 Antigravity）。前端要新字段/新接口 → 你发布契约，对方消费。
- 不做设计决策；不改 L3/L4/L5、PALETTE、`design/`。
- 不制作 `owner = Antigravity` 的资产，不制作任何商品模型。
- 不为"方便"改接口字段名：契约变更是 T2。

## 3. 输入

L5@vNN 手册 · L3/L4（参照）· PALETTE.json（模型材质色用）· 既有 Worker 代码与线上契约。**不是输入**：L1、L2、HANDOFF_*、口头指示。

## 4. 开工前（零中途追问）

同 Antigravity：对每个资产与每个接口，把疑问全部写入 `ASSET_MANIFEST` / `API_ASK` 一次提交；"批准施工"前不动代码、不部署。

## 5. Cloudflare 规范

| 项 | 规则 |
|---|---|
| 目录 | `workers/<名>/`、`contracts/<名>.md`（或 openapi.json）；Drive 路径 `cloudflare/<事项>/cursor/`、`agent/<事项>/cursor/` |
| 契约 | 路径、方法、参数、返回字段、错误码、缓存 TTL、CORS 来源；**向后兼容**（只增字段，不删不改义） |
| 稳定性 | 失败返回结构化错误，不返回 HTML；前端 3 秒超时可静默回退，所以接口必须快失败 |
| 运费/收款 | 影响结算的改动先用真实一单验证再合入；不得改动结算相关默认值而不走 T3 |
| 秘密 | 不进仓库；用 Cloudflare secrets；PR 内出现密钥即判失败 |
| 环境 | staging 先行；生产部署只在你"批准合入"之后 |
| 数据 | D1 迁移文件只增；回滚脚本必备 |
| 可观测 | L5 FLOWCONTRACT 第八节的事件必须有日志/计数 |

## 6. 智能体规范

- 能力边界以 L5 手册为准；不新增 L5 没有的工具、权限、话术。
- 不得用人物/吉祥物形象包装智能体；G-0 为 ⌀24mm 虚线圈槽位，形体只能按 `AGENT_ASSET_REGISTRY` 注册的资产。
- 不得产出倒计时、虚假稀缺、未经接口确认的价格/时效/库存。
- 必须有降级：智能体不可用时，页面回到常规内容，不出错误弹窗。
- 不记录超出 L5 声明的用户数据。

### 6A. 智能体与模型资产的关系（隔离从宽）
- 全生态模型资产内部有智能交互；智能体对外对内互联，**生态模型资产在需要时完全可由智能体调用**。因此：所有生态资产（无论 owner 是谁）自动登记进 `AGENT_ASSET_REGISTRY`，智能体可读取与调用，无需逐个申请。
- 隔离只保留两条：(1) 智能体不得**改写**他人 owner 的资产文件；(2) 调用不得突破 Hot/Cold 预算与降级要求（智能体不可用时页面照常）。
- 其余不再设强隔离：智能体代码与资产的接口（调用名、状态事件）由契约 `contracts/agent-assets.md` 描述即可。

## 7. 3D 资产规范

**衡量标准＝精细度**（不是维度）：造型精度、边缘与倒角、材质与接缝光的真实度、细节层级、在目标视距下的可辨识度——先定"精细度目标"写进 ASSET_MANIFEST，按目标验收；预算（面数/体积/Hot）仍必须守。流水线、Promote 状态、材质色相带同 Antigravity 协议 §6。路径 `assets/3d/ecosystem/cu/<id>/`，**严禁写入 `ecosystem/ag/` 与 `products/`**。

## 7A. 算力不足时：写 TRACK 进 Drive（v2.1 新增）

当 Cursor 的算力/额度不支持继续推进某个资产或事项时，**停在安全点并写 TRACK，不静默中断、不留半成品在主干**：
- 位置：Drive `model-ecosystem/<id>/cursor/TRACK.md`（其他事项同理 `<类别>/<事项>/cursor/TRACK.md`）；仓库镜像 `track/TRACK_<id>.md`。
- 内容（固定字段）：`STATUS: HANDOVER`｜L5 版本｜Promote 状态 S?｜精细度目标 vs 现状（逐项）｜已交付文件与 sha256｜未完成清单（按优先级）｜续作命令/工具链与参数｜已知问题与决策记录｜算力停止原因｜接手记录（留空）。
- 要求：写完 TRACK 即可停；Antigravity 据此追踪并继续（见 Antigravity 协议 §6A）；精细度标准不降。
- 在 TRACK 里区分 `DONE / IN_PROGRESS / NOT_STARTED`，不夸大完成度。

## 8. 四道硬闸

1. **L5 一致**（逐条证据）；
2. **契约兼容**（旧前端调用仍通过；契约测试脚本在 PR 中）；
3. **稳定性**（超时、5xx、空库、限流、关闭智能体五场景）；
4. **资产预算**（同上）。

## 9. 提交流程

分支 `cu/<模块>-<L5版本>` → PR（含 `L5@vNN`）→ CI → 你"批准合入"。部署与合入分两步，合入后才部署生产。

## 10. 变更控制 / 验证 / 完成定义

与 Antigravity 协议 §9–§11 相同（变更单 `change/CR-*.md`；`VERIFY_*` 自写自改；四闸 + 无空项 + 变更单有裁决 + 批准合入）。

## 11. 与旧协议相比的关键变化

- 删除：Cursor/Grok 做网页施工的全部条款、"Grok"字样。
- 新增：智能体开发正式归入；精细度标准；算力不足 TRACK 机制；智能体可调用全部生态资产；生态模型归属规则；契约兼容为硬闸。
- 修正：Cursor 不再做 Shopline 主题接入。
