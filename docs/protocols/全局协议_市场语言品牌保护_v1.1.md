# 全局协议：市场 / 货币 / 语言 / 品牌保护 v1.1

更新：2026-11-28（v1.1：默认语言英文、其他语言由后台插件应用；币种三层规则，结算币种 HKD）· 类型：全局协议（Gemini、Antigravity、Cursor 全部适用）
落地时机：**后续跑到"全局链接配置"时统一实施**；本协议先定规则，不立即改主题。

## 1. 市场与货币
- **默认市场：US**；默认显示货币 **USD，符号 `$`**。没有路径前缀、没有送达国家记录时，默认按 US 取数（市场、运费、节日）。
- **币种三层规则**（v1.1）：
| 层 | 规则 |
|---|---|
| 显示币种 | 访客所在市场的**本地币种**（默认市场 US → `$` USD） |
| 可支付币种 | **只能用本地币种支付**，不提供跨币种选择（local 只能付 local 币种） |
| 结算币种 | **最终接受的货币是 HKD**；本地币种支付后**自动换算为 HKD** |
- "local"我理解为访客所在市场（路径前缀）的本地币种。**待你定**：某个市场的本地币种平台不支持支付时怎么处理。
- **对设计与施工的约束**：
  1. 零数据前端：价格、汇率、手续费一律来自平台/接口，前端不得自行换算、估算或写死汇率。
  2. 展示的金额必须＝实际支付的本地币种金额；金额旁带币种标识（`$` 与币种代码在易混场景下并列）。
  3. 信任信息（D-09 的 Trust 段）要包含"以本地币种支付、系统自动换算为 HKD 结算"的一句说明；具体文案由你定，汇率与手续费以支付渠道为准，不写具体数字。
  4. Cursor 的 Worker 契约：凡返回金额的接口，必须带 `currency`（ISO 代码）字段；基准为 HKD 的数据在返回前按平台规则呈现为本地币种，不由前端换算。
  5. 购物车/结账属最低 DNA 档，币种说明用最克制的版式。
- 现状差异（待实施清单）：主题骨架 0.1.0 与 `sv-core.js` 的默认市场写的是 `hk`，项目文档 14 也据此描述。**到全局链接配置时统一改为 us**，同时核对：主题设置里的默认市场、运费 Worker 的默认国家、金额格式与 `$`、币种说明、`sv_ship_to` 的兜底。
- 其他市场（路径前缀）保持现有机制不变，只改"默认"。

## 2. 语言
1. **默认语言：英文。其他语言由后台插件应用（翻译/多语言应用）实现，不在代码侧做**。
2. **不做语言学习与收录**：不为 i18n 建翻译记忆/词库，学习记录里也不收录翻译类条目。
3. **后台编辑区固定英文**：编辑器 schema 只提供英文（`en.schema.json`）。主题骨架 0.1.0 里我加的 `zh-hans-cn / zh-hant-tw` 编辑器译文，到全局链接配置时清理。说明：Shopline 后台界面语言可能随账号设置，我没法在这里确认能否强制；以"我们只提供英文标签"为准。
4. **前台使用语言切换器**：访客自行切换；前台文案以 `i18n/en.json` 为唯一键源，其他语言的文案由插件应用生成。
5. 新增可见文案：只加 `en.json` 键，不再补其他语言。
6. 插件翻译与品牌保护衔接：在插件里配置"不翻译词汇表"＝品牌保护词表（§3）；上线前对插件翻译输出抽检品牌词（到全局链接配置时落地）。

## 3. 品牌保护（相关词语不得翻译）
1. 建立**品牌保护词表** `design/BRAND_TERMS.json`（由你与 Gemini 维护；施工方只读）。已确认的词：`SpaceVanta`、`Space Vanta`。**其余词（系列名、产品线名、Season 名称、标语等）我没有资料，请你补。**
2. 词表里的词在**任何语言**下都**不翻译、不音译、不改大小写、不拆写**。适用范围：页面文案、导航、按钮、SEO 标题/描述、图片替代文本、结构化数据、邮件/通知、智能体话术、Logo 字标。
3. 实施规则（到全局链接配置时落地）：
   - 前台输出时给品牌词加不翻译标记（`translate="no"` 与 `notranslate` 类），避免浏览器/翻译应用改写；
   - i18n 文件中的品牌词在所有语言文件里必须与词表**逐字一致**；
   - CI 检查：扫描 i18n、模板与元数据，发现词表词的变体或译文即失败（检查脚本后续随全局链接配置一并提供，**当前没有**）；
   - Gemini 的 L5 在"禁止项"里引用词表，不得设计出需要翻译品牌词的文案位。
4. 语言切换器自身的语言名称用各语言的自称，不属于品牌词。
