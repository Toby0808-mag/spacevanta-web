# 模型自动化迭代协议（U 系列）v1.0

更新：2026-11-28 · 类型：增量补录协议 · 参与方：Gemini、Antigravity、Cursor、你
默认适用范围：**模型资产**（商品模型、全生态模型、智能体）及其当前 L5。若你希望同样用于网页模板，告诉我，改一行范围即可（**待确认**）。

## 1. 总览

U 系列是"自动探索 → 设计把关 → 你批准施工"的三段迭代。**自动探索只发生在沙箱里，不碰主干、不改 L3/L4/L5。**

```
U1  Gemini 出方向单 ──→ 施工方自动跑（定量 token 限额）──→ 提交"所跑方向"（有无结论都交）──→ 你批准
U2  施工方发现可能性 ──→ Drive+GitHub 双端保存 ──→ Gemini：L4-Check-A → L4-A → L5-A
         └ 同理迭代 B、C…：L4-Check-B → L4-B → L5-B
U3  你批准 ──→ 按 L5-X 进入正式施工（走全部既有闸门）
```

## 2. U1：方向单 → 自动跑 → 提交 → 批准

**Gemini 出方向单** `U1_<事项>_方向单.md`，内容是：
- 当前 L5 设计里出现的**缺陷**；
- **全生态**可以升级的**功能**与**展示**。
每个方向一行：`id`、类型（缺陷/功能/展示）、描述、假设（改了什么、预期改善哪项指标）、边界（只能在 E1 档内，不得动 E0、DNA 强度档上限、预算）、**单方向 token 上限**、停止条件。方向单头部必须有**总 token 限额（`token_quota`，必填）**：限额由你设定；没有限额，施工方不得开跑。

**施工方自动跑**（Antigravity 与 Cursor 各跑属于自己范围的方向）：
1. 先过学习记录（`review`），已失败的路线不重复；
2. 在沙箱分支 `ag-u/<事项>-U1`、`cu-u/<事项>-U1` 内跑，产出只放 `u-runs/<角色>/U1/<方向id>/`（Drive：`<类别>/<事项>/<角色>/U/U1/<方向id>/`）；
3. **到额度即停，不超额、不透支下一个方向的额度**；低收益早停；
4. **无论是否有结论，都要提交所跑的方向**：`U1_run_<方向id>.md`，写明结论（有结论·正向 / 有结论·负向 / 无结论 / 额度截停）、证据、**实际用掉的 token**、产出路径；
5. 每个方向都写学习记录（失败点、通过点、`--next`）。

**你批准**：对每个提交的方向给"批准 / 搁置 / 否决"。批准的才进入 U2 的考虑；搁置/否决的结果仍保留在学习记录里。

## 3. U2：发现可能性 → 双端保存 → Gemini 三步

**施工方发现可能性**（来自 U1，或自动跑中的额外发现）：写 `U2_<序号>_<标题>.md`：发现了什么、证据、如何复现、影响面（涉及哪些资产/页面/接口）、风险、与 L5 的差异。
**双端保存**：同一份内容同时存 **Drive**（`<类别>/<事项>/<角色>/U/U2/`）与 **GitHub**（`u-runs/<角色>/U2/`），并各附 `SHA256SUMS`，两端哈希必须一致。

**Gemini 接受后走三步（迭代 A）：**
| 步 | 文件 | 做什么 | 出口 |
|---|---|---|---|
| 1 | `L4-Check-A` | 轻量可行性预审：对 D-01…D-09、DNA/PALETTE、预算做预判，并确认施工方做得出来 | 可实现 / 需调整（回施工方）/ 否决 |
| 2 | `L4-A` | 对"可实现"的方向做完整九维评审与就地改进（规则同 L4） | 全绿或琥珀已批准 |
| 3 | `L5-A` | 施工对齐手稿（新版本 `vNN-A`，规则同 L5：只增不改不删） | 签发 |

**迭代 B、C…** 同理：`L4-Check-B → L4-B → L5-B`。后一轮默认以上一轮**已签发**的 L5-X 为基线，除非你指定。
文件处理：`L4-Check-X`、`L4-X` 沿用 L3/L4 的"删旧留新 + PRESENT_LOG 留痕"；`L5-X` 永久备份。
路径：Drive `<类别>/<事项>/Gemini/L4-Check-A/`、`L4-A/`、`L5/vNN-A/`；仓库 `design/<类别>/<事项>/L5/vNN-A/`。

## 4. U3：你批准 → 正式施工

- 你对某个 `L5-X` 说"**批准 U3-X**"，施工方才可以开正式分支（`ag/*`、`cu/*`）。
- 之后与普通施工完全一致：PR 标题写 `L5@vNN-X`；学习记录、交付清单、代码清单、五道/四道硬闸全部适用；你"批准合入"。
- 没有你的 U3 批准，U2 的任何结果都不得进入主干。

## 5. 约束汇总

| 项 | 规则 |
|---|---|
| 沙箱 | 自动跑只在 `ag-u/*`、`cu-u/*`；CI 只允许它们写 `u-runs/<角色>/` 与自己的学习记录 |
| 额度 | `token_quota` 必填；超额视为违规；未用完的额度不累计到下轮（**待确认**） |
| 不浪费 | 同一方向不重复跑已失败路线；低收益早停；方向单里每条都有停止条件 |
| 不越界 | 施工方在 U 阶段**不做设计结论**，只报告发现；Gemini 不动手建造 |
| 红线 | 任何 U 方向都不得突破 E0、品牌禁止清单、预算、r3 光外溢上限；突破＝T3，需你亲批 |
| 留痕 | U1 提交、U2 发现、L4-Check/L4/L5-X、你的批准，都写进 `PRESENT_LOG` |

## 6. 命令与权限小结

- 你的指令新增：对 U1 方向"批准/搁置/否决"；"批准 U3-X"。
- 施工方：`ag-u/*`、`cu-u/*` 沙箱分支；产出目录 `u-runs/`。
- Gemini：写 `U1` 方向单、`L4-Check-X`、`L4-X`、`L5-X`。

## 7. 待你确认（我的理解与默认）
1. "模型自动化"默认只覆盖模型资产与智能体，可扩展到网页模板。
2. 迭代编号用 A/B/C，L5-X 的版本号形如 `v03-A`。
3. 总 token 限额由你设定，没有默认数值。
4. U2 由 Gemini 直接接受（不需要你先批准），只在 U3 需要你批准。
