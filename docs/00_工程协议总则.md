## 1. 原则
1. 设计与施工互不越界：Gemini 只设计；施工方只建造。
2. 施工只按 L5。L5 与 L3/L4 冲突以 L5 为准。
3. 零中途追问：开工前一次问完；之后只走变更单。
4. 不浪费：工具、算力、变体都要有目的与止损。
5. 品牌 DNA 与 PALETTE 优先于一切审美偏好。

## 2. 角色
| 角色 | 做 | 不做 |
|---|---|---|
| Gemini | L1–L5；可调用多工具（须不浪费） | 建模、写站/Worker/智能体 |
| Antigravity | 网页、商品 3D、owner=ag 的生态 3D；基准线后受控变体 | 设计决策、Cloudflare/智能体 |
| Cursor | Cloudflare、智能体、owner=cu 的生态 3D（精细度标准） | 设计决策、主题网页、商品模型 |
| 用户 | 批准立项 / 批准施工 / 批准合入 / 退回 | — |

## 3. L1–L5
| 级 | 内容 | 给谁 | 文件处理 |
|---|---|---|---|
| L1 | 概念图 | 用户 | 可覆盖 |
| L2 | 初步设计稿 | 用户 | 可覆盖 |
| L3 | 实体交互式预演 | 用户 + 施工方 | 退回更新删旧留新，PRESENT_LOG 留痕 |
| L4 | 九维评审与改进 | 用户 + 施工方 | 同 L3 |
| L5 | 施工对齐手稿 | 施工方 | 每次迭代新版本，永不删改 |
L3/L4/L5 文件类型不限，必带 .md 说明书。

## 3A. 模型/智能体的 L3 默认三档（r1/r2/r3）
商品模型、全生态模型、智能体在 L3 默认交付 r1/r2/r3（累进）：**r1** 模型使用、细节都够看；**r2** 扣热点并按梯度逐步开放模型自带 3D 动效；**r3** 中心大模型化，允许受控"光污染"（预授权琥珀，限舞台容器内，不覆盖文字/CTA/Trust，不改 paper/seam-aura，减少动效或弱网降级）。降级链 r3→r2→r1→海报。每个放置点的目标档 `r_target` 写进 L5，施工建到 `r_target` 为止。商品模型热点数量按"可交互部件清单"定、无统一上限（巧克力礼盒至少 16 个）；光外溢上限已确认：舞台容器 ≤40%、视口 ≤20%。细则见《Gemini 模型交付协议 v1.1》。

## 4. L4 九维
D-01…D-07（沿用 v1.2.1 附录） · D-08 渠道（Desktop SEO + Mobile 快流量承接与转化） · D-09 顺序（Trust → Motivate → Remember，不可倒置）。三色闸 GREEN/AMBER/RED：红必关，琥珀需豁免批准。

## 5. 闸门与指令
批准立项 → L1…L4 → 批准施工（L4 全绿/琥珀已批 + L5 签发）→ 施工 → 硬闸（Antigravity 五道：清单 / L5 一致 / 令牌与色相 / 稳定性 / 资产预算；Cursor 四道：L5 一致 / 契约兼容 / 稳定性 / 资产预算）→ 批准合入。退回 + 原因：回到指定级。

## 6. 目录
**Drive**：`<类别>/<事项>/<角色>/…`，类别 `theme | model-product | model-ecosystem | cloudflare | agent`。例：`theme/hero-bridge/Gemini/L3|L4|L5/…`，`theme/hero-bridge/antigravity/…`。
**仓库**：见根 README。`design/` 为批准后的镜像，施工方只读；Drive 与仓库不必同放。

## 7. 分支与 PR
`ag/*` `cu/*` `ag-u/*` `cu-u/*`（U 沙箱，只写 `u-runs/` 与自己的学习记录）`design/*` `gov/*`。PR 标题含 `L5@vNN`。CI 的 `scripts/check_gates.sh` 强制：角色只能改自己的路径；`design/*/L5/` 只增不改；施工方不碰设计侧受保护文件（L3_/L4_/L5_/ASSET_MAP_/AGENT_ASSET_REGISTRY/PRESENT_LOG_/PALETTE）。

## 8. 变更
T0 错字（自改）· T1 不改行为的实现（自决）· T2 改行为/状态/资产预算/契约（变更单 → Gemini 出 L5 新版 → 用户批准）· T3 改 DNA/品牌/价格运费逻辑（用户亲批，重走 L3–L5）。变更单：`change/CR-*.md`，不得先改后补。

## 9. 资产
- 血统：M-Proto → Mother（不可见）→ Child → Hot（每屏≤3，全站≤4）→ Cold。Promote S0–S5 逐级。
- 每个生态资产在 L5 ASSET_MAP 有唯一 owner；商品模型只归 Antigravity。
- 智能体可随时调用全部生态资产（建造权仍归 owner；调用不破预算与降级）。
- Cursor 资产以**精细度**衡量；Antigravity 资产以**维度**衡量。

## 10. 变体（Antigravity）
基准线过闸后：模板变体 10–20 个（每个先写假设，早停，评分表用 L4 九维）；模型变体 1–2 个（先写"为什么值得跑"）。变体不入主干；提交"基准线 + 最优变体"，用户决定合入。变体只能在 L5 变体边界（E1）内，不得动 E0 与强度档上限。

## 10A. 代码清单（Antigravity，分层）
- **全局清单** `code-checklist/CODE_CHECKLIST.md`（Drive `antigravity/code-checklist/`）：只管全局/驱动层共用代码（layout、components、blocks、sv-dna、i18n、主题配置等）。
- **模板清单** `code-checklist/templates/<模板>/CODE_CHECKLIST.md`（Drive `theme/<模板>/antigravity/code-checklist/`）：只管该模板内部代码；模板内部代码不进全局清单。
- **全局/驱动层（含 `public/` 共有资源）除登记变更外必须保留修改前的源实现**（`source-keep/`）；开工后他人也改了同一文件＝源码冲突，源实现标 HOLD，用户批准后才可修改。
- **清单只留 2–3 份**：当前版 + 最近 2 份备份；日志只留最近 5 条；源实现批次只留最近 3 个（含 HOLD 的不清理）。完整历史以 git 为准。
- 每次施工前 **pull**（对账变动、登记活动锁），施工后 **submit**（台账、变更、释放锁），CI 强制。跨模板调用内部组件：先读对方清单，用 `dep` 登记依赖；多模板共用的组件上升为全局组件。3D 资产不进代码清单。

## 10B. 学习记录、交付清单、重交付（Antigravity 与 Cursor）
- **学习记录**（`learning/<antigravity|cursor>/LEARNING_LOG.md`）：每次施工前先 `review`；每次尝试记通过与失败点；已失败的标签组合不得无理由重复（需 `--differs`）；"基本盘"收录已验证可用的写法/语言，新路线跑不通时回基本盘（fallback）。
- **交付清单**（`delivery/<分支>/MANIFEST.md`）：每次交付只列新增/删除/修改，未改变不列；CI 用 diff 对账。
- **被退回重交付**：先跑 `chain_check.py` 确认链路被准确调用，`CHAIN_CHECK.md` 为 PASS 才放行。

## 10C. U 系列模型自动化迭代
U1：Gemini 出方向单（L5 缺陷 + 全生态升级功能/展示）→ 施工方在沙箱分支（`ag-u/*`、`cu-u/*`）按定量 token 限额自动跑，有无结论都提交所跑方向 → 你批准。U2：施工方发现可能性，Drive 与 GitHub 双端保存 → Gemini 走 L4-Check-A → L4-A → L5-A（迭代 B、C 同理）。U3：你批准后按 L5-X 正式施工（走全部闸门）。

## 10D. 全局约定
默认市场 US、货币 USD（`$`）；后台编辑区固定英文；前台用语言切换器；不做 i18n 语言学习与收录；品牌保护词不得翻译（`design/BRAND_TERMS.json`）。到"全局链接配置"时统一实施。

## 11. TRACK（Cursor 算力不足）
Cursor 写 `track/TRACK_<id>.md`（STATUS: HANDOVER，含 Promote 状态、精细度现状、文件与 sha256、待办、续作参数）并同步 Drive；Antigravity 据此继续，精细度不降；CI 仅在 HANDOVER 时允许 ag 写入 `ecosystem/cu/<id>/`。

## 12. 禁止清单
倒计时 · 虚假稀缺 · 人物/吉祥物 · 节日池中的食物 · 季节皮肤改 paper/paper-subtle/seam-aura · 未经接口确认的价格/时效/库存 · seam 蓝作小号正文 · 站内 hex（令牌定义除外）。
